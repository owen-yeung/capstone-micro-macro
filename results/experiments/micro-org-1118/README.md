# micro-org-1118：单智能体与多智能体微观输出的评分比较

2026-11-18 运行。状态：模型评审已完成，**尚未人工校准，待验收**。

## 做了什么

6 个项目（CASE-0001、0002、0004、0008、0014、0050，覆盖市政、交通、居住、公共服务、产业五类），每个投标角色取 2 家候选企业，在三种组织方式下各跑一遍微观招投标阶段，再用模型评审按 [评分规则 v2](rubric_v2.json) 打分。生成与评审模型都是 `deepseek-flash`。

| 臂 | 做法 |
|---|---|
| `single` | 决策人不经讨论，一次调用给出结论 |
| `solo` | 决策人独自走完相同轮数的讨论再决定 |
| `multi` | 各部门成员分轮讨论，决策人汇总后决定 |

每个阶段三臂收到完全相同的输入；评审看不到输出来自哪个臂。设计和评分方法见 [docs/micro_org_rubric.md](../../../docs/micro_org_rubric.md)，每一档的判档条件见 [docs/micro_org_rubric_levels.md](../../../docs/micro_org_rubric_levels.md)。

## 结果

完整表格在 [REPORT.md](REPORT.md)，数字在 [summary.json](summary.json)。共评 353 份输出。

**1. 多智能体的评分略高，差距主要在“风险与权衡”。**
六项均值：`multi` 4.60，`solo` 4.54，`single` 4.45（1–5 档）。`multi` 减 `single` 的配对差为 +0.15（112 对，按项目重抽样的 95% 区间 0.11 到 0.18，6 个项目方向一致）。分维度看：

| 维度 | multi − single | multi − solo |
|---|---|---|
| R1 决策适当性 | +0.09 | +0.03 |
| R2 关键事项覆盖 | +0.16 | +0.04 |
| R3 可执行性 | +0.21 | +0.04 |
| R4 风险与权衡 | **+0.53** | **+0.24** |
| R5 证据忠实 | 0.00 | 0.00 |
| R6 内部一致与约束遵守 | −0.07 | −0.08 |

**2. 大部分提升来自“多想几轮”，不是“多个岗位”。**
`multi` 减 `solo` 的六项均值差只有 +0.05，区间跨过 0（−0.02 到 0.10）。只有“风险与权衡”一项多岗位讨论明显更好（+0.24，区间 0.10 到 0.34）。

**3. 成本差距远大于质量差距。**
模型请求数 167 / 619 / 1749，输入 tokens 81 万 / 310 万 / 1109 万（`single` / `solo` / `multi`）。`multi` 的输入 tokens 是 `single` 的 13.6 倍、`solo` 的 3.6 倍。

**4. 不同输出类型的收益不同。**
`multi` 减 `single` 的六项均值差：企业投标决策 +0.21，业主招标策划 +0.18（仅 6 份），投标文件 +0.13，评标与定标 +0.07；后两项的区间跨过 0。

**5. 成对比较比逐份评分更偏向多智能体。**
A/B 两种顺序都一致才计胜：`multi` 对 `single` 为 75 胜 14 负 23 不一致（112 对）；对 `solo` 为 64 胜 27 负 21 不一致。但成对比较有 19.6% 的总体结论随呈现顺序改变，74.8% 的判断里各维度结论与总体结论完全相同，区分维度的能力弱，分维度结论以逐份评分为准。

**6. 讨论过程本身：多岗位讨论有实质交流，也有浪费。**
`multi` 的有据新增事项 4.54、意见回应 3.64、角色分化 4.00、吸收进决策 4.74；`solo` 前三项只有 1.78、1.35、1.12。`multi` 有 64% 的讨论被标记重复劳动，16% 有意见被忽略。

**7. 硬性检查三臂接近。**
决定投标后的实际递交率 0.87 / 0.91 / 0.91；因输出两次未过校验而未能递交的投标 6 / 3 / 4 份，多数是报价分项之和与总价不符。

## 读数边界

- 评审与生成是同一个模型，没有人工校准。[human_calibration_sheet.csv](human_calibration_sheet.csv) 是隐去臂标签的 24 份盲评表，[human_calibration_key.json](human_calibration_key.json) 是答案键；人工复评后才能说明模型评分与人的一致程度。
- R5、R6、R2 的均值在 4.7 到 5.0，接近满分，区分度有限。
- 只有 6 个项目，同一项目内的多份输出不是独立样本；项目层区间只作方向参考。
- 下游阶段的共同输入取自 `multi` 臂的上游产物，结果不代表 `single` 全流程自洽运行的表现。
- 分数是量表等级，不是现实中标率或工程合格率。
- 评审可靠性：同一份输出两次评分完全一致 75%，相差不超过 1 档 96%；评审引用的原文 99.1% 能在被评输出中逐字找到。
- 与冻结 CP07 组织对照 [`org_deliberation_metrics_20261119`](../org_deliberation_metrics_20261119/SUMMARY.md) 互补（题面、臂定义、量表均不同）；不可与该电池分数合并。臂名叙述类比仅作：single≈S，solo≈S4，multi≈D3。

## 复现

```powershell
uv run python -m scripts.micro_org_experiment --cases CASE-0014,CASE-0001,CASE-0002,CASE-0004,CASE-0008,CASE-0050 --per-role 2 --profile full --parallel-cases 3 --output runs/<新目录>
uv run python -m scripts.micro_org_judge --experiment runs/<新目录> --pairs single:multi,solo:multi
```

两条命令都调用真实模型。本次用量：生成 2535 次请求、约 1500 万输入 tokens；评审 1422 次请求、约 677 万输入 tokens。解压 `full_run.zip` 后对其重跑评审命令会直接命中缓存。
