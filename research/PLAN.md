# 当前研究主线与实验设计

## 研究目的

在相同业务事实与约束下，检验企业的个体判断、岗位审议和复核怎样影响业务决策质量，并追查这些决定是否进入交易、项目模拟后果和后轮反馈。

研究贡献集中在微观业务判断与组织机制。宏观程序作为环境和执行平台使用，不将其已有工程模型当作本研究原创贡献。工程闭环可运行、回答质量改善、现实工程有效性是不同层次的证据。

## 研究问题与比较

| 问题 | 对照与观察 | 核心产物 |
|---|---|---|
| RQ1 业务判断质量 | 相同题面和事实下，原生成实现与当前生成实现，完整/缺资料情景分别评分 | 行动适当、关键事项覆盖及方案等级 |
| RQ2 组织机制 | 单次生成、同角色四步、多岗位审议后定稿。主要比较后两者 | 质量差、意见处理、实际策略与资源成本 |
| RQ3 反馈响应 | 相同机会的无反馈/相关结算反馈；地区与金额另作控制 | 按预定规则应变及主导约束保持 |
| RQ4 项目后果 | 同一来源下规则、单次、岗位审议、同角色复核的原生宏观对照 | 报价、签约、成本、进度、质量、风险、里程碑和业务扰动 |

推荐部分是数据与检索支撑：画像规则、角色频次、角色加地区、相似项目历史经验，在相同历史角色单元上比较。它不是LLM业务回答准确率。

## 全量目标与冻结实验范围

原始数据有352条项目记录，当前去重为331个项目组，企业904家，历史关系499行，433个有标签的项目与角色单元。

后续目标是331组逐组适配并记录执行去向，所有可适配项目形成统一业务任务及评价。现有冻结业务范围为先期48组加新增232组，共280组；另44个开发使用组和7个缺字段组需要补齐任务或资料，不能把资料盘点算成实验完成。

组织对照复用项目，不额外增加总体项目数。宏观原规划最多27个源候选，须核对模式、地区、领域和项目家族。完整微观业务任务可适用，不自动意味着同一项目适合现有宏观DBB链。

## 评价Taxonomy

| 类别 | 指标 |
|---|---|
| 个体业务质量 | D1决策适当率；D2关键事项正确覆盖；D3可执行性0-2等级；D4权衡质量0-2等级 |
| 组织机制 | O1有据新增事项；O2有效事项回应；O3最终质量成对差；O4语义策略分歧 |
| 交易与宏观 | T1定价；T2签约价/预算；T3成本偏差；T4进度与时序；T5质量；T6风险；T7完成状态；T8检查与业务事件 |
| 后轮反馈 | F1相关反馈适当响应；F2应不变条件保持 |

各指标独立报告，不合成系统总分。方案等级与比例不同；模型质量/风险指数不是现实合格率或事故概率。相同调用次数不等于相同tokens。

## 分析与证据原则

先评分并保存正文引文、输入位置和理由，再复核。当前为研究者辅助AI评价，不能称为独立专家或外部盲评。初始回答与定向修正分开保存，修正不替换首轮。项目先在自身情景与重复内聚合，再参与项目等权比较；不同设置和数据家族分层，不将大量回答或时点当作独立项目。

面向不熟悉仓库读者的证据链路说明见[数据生命周期](DATA_LIFECYCLE.md)（档案资料 → 任务卡 → 生成与门禁 → 有引文评阅 → 冻结入库）。

### 生成校验增强（前向流程，不改写冻结评分）

后续待评与新批评阅按[生成校验说明](generation_validation/README.md)执行，工具入口为 `scripts/enhance_generation_validation_20261117.py`：

1. 机械门禁：可读性、必填栏目、疑似编造事实与D1模式启发式；只产出结构化代码，不自动给D1–D4。
2. 结构化评分表：第二模型族草稿与裁决分栏；只报告草稿–裁决一致，不称评阅者间一致性。
3. 扩展判别锚点：24个持出构造例，正式批次前漂移检查；只向前重校准，不回改历史分。
4. 去标识与顺序互换：先单答后成对；剥离版本标签；可全量或按角色分层固定哈希抽对；泄露标记单独记录。
5. 覆盖表：角色×资料×条件×取舍单元与挑战类宣称门禁；无覆盖则收窄论文主张。
6. 专家薄切片：24–48份分层样本作外部可信度对照，专家标签另存，不替换冻结评分。

已有结果和完成度以[结果导航](../results/README.md)为准。当前汇报中的85.7%是已评当前生成实现首轮回答的行动适当比例，不是相对基线的提升，也不是全量331组成功率。
